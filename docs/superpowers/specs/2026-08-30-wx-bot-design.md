# 微信机器人项目设计文档

## 1. 文档目的

本文档根据《微信机器人.md》及已确认的方案，定义微信机器人的首版目标、技术路线、系统架构、数据流、开发边界、风险和验收标准。

本文档是设计文档，不代表已经开始实现。未经用户进一步确认，不创建实现代码、不连接微信、不调用 AI 接口，也不发送微信消息。

## 2. 需求来源与授权边界

### 2.1 文档中的项目要求

原始需求文档提出：

- 制作支持单聊和群聊的微信机器人。
- 能够分析群聊信息。
- 读取微信本地 SQLite 数据库中的聊天记录。
- 将信息发送给 DeepSeek 模型。
- 获取 AI 返回内容后，通过 UI 控制微信回复消息。
- 参考项目：[wechatauto-replica](https://github.com/fanyuantaier/wechatauto-replica)。

### 2.2 用户明确授权

当前用户授权范围为：

- 先制定并整理项目方案。
- 用户确认方案后再进入开发。
- 当前已确认总体方向和详细设计，并要求整理为项目文档。

因此，本阶段只产出设计文档，不执行实现工作。

## 3. 目标与非目标

### 3.1 项目目标

构建一个运行在 Windows 本地的微信机器人，首版支持：

- 指定单聊和指定群聊监听。
- 增量读取新消息。
- 调用 DeepSeek 生成回复或分析结果。
- 通过规则控制单聊、群聊的触发条件。
- 通过微信 UI 自动化发送消息。
- 默认采用人工确认发送。
- 提供基础群聊总结和信息分析能力。
- 提供日志、暂停、恢复和安全退出能力。

首个兼容性目标为 Windows 微信 `4.1.13.12`。

### 3.2 非目标

首版不包含：

- 批量群发。
- 自动加好友或自动拉群。
- 多账号管理。
- 绕过微信安全机制的功能。
- 大规模营销或高频自动发送。
- 修改微信原始数据库。

## 4. 推荐技术路线

采用以下本地架构：

> Python 本地桌面程序 + 微信 SQLite 只读读取 + DeepSeek API + Windows UI 自动化 + 默认人工确认发送

选择该路线的原因：

- 与原始需求中的 SQLite、AI 和 UI 控制思路一致。
- 不需要修改微信客户端。
- 数据读取、AI 调用和消息发送可以分模块测试。
- 微信版本变化时，可以单独替换数据库适配器或 UI 适配器。

不采用协议 Hook 或客户端注入作为首版方案，因为其账号风险、维护成本和版本耦合更高。

## 5. 系统架构

```text
微信客户端
   │
   ├── SQLite 只读读取 ──> 消息采集模块
   │                         │
   │                         ▼
   │                    消息过滤与上下文模块
   │                         │
   │                         ▼
   │                    DeepSeek 接口模块
   │                         │
   │                         ▼
   │                    回复策略模块
   │                         │
   │                         ▼
   └──── Windows UI 自动化发送 <── 回复确认模块
```

### 5.1 模块职责

- **数据库适配器**：定位并只读访问微信数据库，隔离微信版本差异。
- **消息采集器**：轮询或增量读取新消息，维护消息游标。
- **会话管理器**：管理单聊、群聊、监听名单和上下文。
- **AI 服务适配器**：调用 DeepSeek，统一处理超时、重试和错误。
- **回复策略引擎**：判断是否回复、回复内容以及是否需要人工确认。
- **微信发送器**：通过 Windows UI 自动化完成选中会话、输入和发送。
- **配置与日志模块**：保存配置、运行状态和诊断信息。
- **桌面控制台**：启动、暂停、查看日志和修改规则。

### 5.2 设计原则

1. 数据库只读，不修改微信原始数据。
2. 默认只监听白名单会话。
3. 群聊默认仅在被 @ 或关键词触发时回复。
4. 首版默认人工确认发送。
5. API Key 只从环境变量或未提交的本地配置文件读取。
6. 数据库结构、AI 服务和 UI 自动化均通过适配器隔离。

## 6. 核心数据流

```text
读取新消息
  ↓
判断是否已处理
  ↓
判断是否属于监听对象
  ↓
提取会话上下文
  ↓
判断触发条件
  ↓
调用 DeepSeek
  ↓
生成回复或分析结果
  ↓
人工确认或自动发送
  ↓
记录结果
```

### 6.1 首次运行流程

1. 检测操作系统、微信进程和微信版本。
2. 用户选择或确认微信数据库目录。
3. 以只读方式验证数据库可访问性和字段结构。
4. 用户配置 DeepSeek API Key 和模型参数。
5. 用户选择需要监听的好友或群聊。
6. 进入“监听但不发送”的测试模式。
7. 用户确认测试结果后，再开启人工确认发送或指定范围的自动发送。

## 7. 消息与回复规则

### 7.1 单聊

支持以下模式：

- 指定好友消息均触发回复。
- 仅关键词触发回复。
- 仅手动指令触发回复。
- 暂停自动回复，但继续记录消息。

首版默认采用“指定好友 + 人工确认”。

### 7.2 群聊

群聊默认不对每条消息回复，仅在以下情况触发：

- 有人 @机器人。
- 消息包含配置关键词。
- 用户手动执行“总结本群最近消息”。
- 达到定时总结条件。

群聊上下文默认读取最近 30 条消息，允许配置为 10～100 条。

### 7.3 群聊分析

首版支持：

- 总结最近消息。
- 提取待办事项。
- 提取重要决定。
- 总结不同成员的主要观点。
- 基于当前群聊记录回答问题。

分析结果的发送范围应可配置为：仅回复触发者，或发送回群聊。

### 7.4 防误回复检查

每条消息在进入 AI 调用或发送前，依次检查：

- 是否属于白名单会话。
- 是否来自机器人自己。
- 是否已经处理过。
- 是否处于冷却时间。
- 是否超过当日调用次数。
- 是否包含禁止处理的内容。
- 是否需要人工确认。

## 8. 发送模式

提供三种模式：

1. **预览模式**：只显示 AI 回复，不操作微信。
2. **人工确认模式**：用户确认后才通过 UI 发送。
3. **自动发送模式**：满足规则后自动发送。

默认使用人工确认模式。自动发送只能由用户对指定会话单独开启。

## 9. 配置与本地数据

### 9.1 配置项

- 微信数据库目录。
- 监听好友和群聊白名单。
- DeepSeek API 地址。
- DeepSeek API Key。
- 模型名称。
- 上下文消息数量。
- 触发关键词。
- 回复冷却时间。
- 每日最大调用次数。
- 发送模式。
- 群聊分析结果发送方式。
- 日志保留天数。

### 9.2 本地保存内容

只保存运行所需数据：

- 已处理消息 ID。
- 消息游标。
- 会话配置。
- 运行日志。
- AI 请求错误记录。
- 可选的短期上下文缓存。

默认不长期保存完整聊天内容。日志中的消息内容应支持关闭或脱敏。

## 11. 开发阶段

### 阶段 0：微信兼容性探测

针对微信 `4.1.13.12`，只进行只读验证：

- 微信进程和窗口识别。
- 数据库文件位置探测。
- 数据库是否可读。
- 表结构和字段类型检查。
- 读取最近一条单聊和群聊消息。
- 确认数据库锁定、加密或权限问题。

本阶段不调用 AI，也不发送微信消息。

### 阶段 1：消息读取

- 增量读取新消息。
- 识别单聊和群聊。
- 消息去重。
- 监听名单。
- 消息游标保存。

### 阶段 2：DeepSeek 接口

- 配置加载。
- 请求和响应解析。
- 超时、重试和限流。
- 上下文拼接。
- 日志脱敏。

### 阶段 3：预览与人工确认

- 生成回复预览。
- 人工确认窗口。
- 暂不自动发送。
- 保存待发送内容。

### 阶段 4：微信 UI 发送

- 定位微信会话。
- 输入并发送文本。
- 检测发送结果。
- 失败重试和人工接管。

### 阶段 5：群聊分析与桌面界面

- 群聊总结。
- 待办提取。
- 关键词和 @ 触发。
- 配置界面。
- 运行状态和日志查看。

## 12. 测试与验收

### 12.1 数据库读取测试

- 找到微信数据库。
- 读取单聊消息。
- 读取群聊消息。
- 正确识别中文、表情和文本消息。
- 微信重启后仍可读取。
- 数据库锁定时安全退出。

### 12.2 AI 接口测试

- 正常请求与回复。
- API Key 错误。
- 网络断开。
- 请求超时。
- 空回复。
- 连续调用限流。
- 超长上下文截断。

### 12.3 UI 自动化测试

- 识别微信窗口。
- 定位指定会话。
- 输入中文和换行文本。
- 正确发送。
- 处理窗口最小化、遮挡或失焦。
- 微信版本变化时给出明确失败提示。

### 12.4 端到端测试

- 单聊触发并人工确认发送。
- 群聊 @机器人后回复。
- 非白名单群聊不响应。
- 重启后不重复回复。
- AI 失败时不误发送。
- UI 发送失败时保留回复内容。
- 暂停机器人后不再调用 AI。

### 12.5 首版完成标准

- 能稳定识别指定单聊和群聊的新消息。
- 相同消息不会重复处理。
- 能正确调用 DeepSeek 并显示回复。
- 人工确认后能通过微信 UI 发送。
- 群聊只有满足触发规则时才回复。
- 数据库或 UI 失败不会导致误发。
- API Key 不出现在源代码和普通日志中。
- 程序可以暂停、恢复和安全退出。

## 13. 风险与应对

### 13.1 微信版本兼容性

数据库路径、结构、加密方式和 UI 控件可能发生变化。

应对方式：将数据库读取和 UI 控制隔离为适配器，并把兼容性探测作为第一阶段。

### 13.2 账号安全

频繁或异常自动化行为可能增加账号风险。

应对方式：白名单、冷却时间、每日调用上限、人工确认和低频发送；不实现批量群发或高风险账号操作。

### 13.3 隐私安全

聊天内容可能被发送至 AI 服务。

应对方式：最小化上下文、敏感信息过滤、日志脱敏、可关闭完整消息日志，并由用户自行配置 API 服务。

### 13.4 数据库读取权限

微信数据库可能被锁定、加密或受到权限限制。

应对方式：首阶段只读验证；若无法稳定读取，则暂停后续自动回复开发并报告具体阻塞原因。

### 13.5 UI 自动化可靠性

微信界面调整可能造成定位失败或发送状态无法确认。

应对方式：发送结果检测、失败保留、人工接管和版本诊断日志。

- 本设计文档通过用户审阅。

- 用户自行准备 DeepSeek API Key。
- 明确测试期间优先使用预览模式或人工确认模式。
