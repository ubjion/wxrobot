# 提示词优化子 Agent 设计

## 目标

为微信机器人增加一个独立的提示词优化子 Agent。它收集脱敏后的对话与运行指标，结合人工反馈分析回复质量，并生成可供人工审核的系统提示词候选版本。

子 Agent 不自动覆盖当前提示词，不改变工具调用逻辑、授权规则或机器人权限。优化失败不得影响正常消息回复。

## 范围

本次实现包括：

- 记录脱敏后的用户问题、机器人回复和运行指标；
- 使用记录 ID 关联人工 `good`/`bad` 反馈和可选原因；
- 每累计 50 条尚未分析的交互自动触发优化；
- 支持通过控制台手动触发优化；
- 异步调用现有 DeepSeek 客户端进行分析并生成候选提示词；
- 保存候选提示词、分析报告和来源元数据；
- 自动校验候选提示词的完整性与安全边界；
- 提供候选列表查看命令。

本次不包括：

- 自动启用或覆盖 `prompts/assistant_system.md`；
- 在线 A/B 测试；
- 修改搜索、天气、知识库、发送或授权逻辑；
- 将日志或候选同步到外部服务。

## 架构

采用同一进程中的独立后台服务。主回复链路只负责生成回复和追加日志；`PromptOptimizerAgent` 在后台读取新增日志并生成候选。二者通过持久化存储边界协作，不共享可变的提示词状态。

### InteractionLogStore

以 JSONL 追加方式保存交互，每条记录包含：

- 唯一记录 ID；
- 时间戳；
- 匿名会话 ID；
- 脱敏后的用户问题；
- 脱敏后的机器人回复；
- 回复耗时；
- 是否发生异常或使用兜底回复；
- 当前提示词版本标识。

当前提示词版本使用提示词内容的 SHA-256 摘要。日志追加成功后，应用运行日志输出记录 ID，供操作者提交反馈。日志追加失败只写入运行日志，不阻断正常回复。

### FeedbackStore

持久化人工反馈，每条反馈包含：

- 对应交互记录 ID；
- `good` 或 `bad`；
- 可选原因；
- 反馈时间。

反馈写入前验证记录 ID 存在。对同一记录再次提交反馈时，以最新反馈为准。

### PromptOptimizerAgent

负责：

- 统计自上次成功分析游标之后的新交互；
- 在达到 50 条时自动提交后台优化任务；
- 响应控制台手动优化命令；
- 合并交互日志、人工反馈和运行指标；
- 调用 DeepSeek 生成结构化分析及完整候选提示词；
- 校验并保存候选结果；
- 仅在成功保存候选后推进处理游标。

同一时间最多运行一个优化任务。任务运行期间的重复触发返回“优化任务正在运行”，不再排队。

### CandidateStore

候选保存在 `prompts/candidates/<版本标识>/`。每个目录包含：

- `prompt.md`：完整候选系统提示词；
- `report.json`：样本数量、反馈统计、主要问题、修改摘要、风险项和校验状态；
- `source.json`：基础提示词版本、日志起止游标和生成时间，不包含对话正文。

版本标识由 UTC 时间戳和递增序号组成，避免覆盖已有候选。

## 数据流

1. `AiReplyService` 开始处理文本消息时记录开始时间。
2. 主服务按现有逻辑生成回复；异常时仍按现有方式返回兜底回复。
3. 回复完成后生成记录 ID，对问题、回复和会话标识执行脱敏。
4. `InteractionLogStore` 追加一条交互记录。
5. 子 Agent 检查尚未分析的记录数；达到 50 条时异步启动优化。
6. 用户可通过 `feedback <记录ID> good|bad [原因]` 补充反馈。
7. 用户可通过 `optimize-prompt` 手动启动优化，不受 50 条阈值限制；没有新记录时返回明确提示，不生成空候选。
8. 子 Agent 让 DeepSeek 先输出结构化分析，再输出完整候选提示词。
9. 候选与校验结果写入候选目录；只要候选和报告完整落盘，就推进已分析游标。
10. `prompt-candidates` 列出候选版本、状态、样本数和生成时间。

优化处理期间，主回复链路继续运行。优化开始后新产生的日志不加入当前批次，留给下一批处理。

## 脱敏规则

日志保存前执行确定性脱敏：

- 微信 ID 替换为稳定匿名编号；
- 手机号、邮箱和身份证号替换为对应类型占位符；
- API Key、Bearer Token、疑似密钥及密码字段替换为 `[SECRET]`；
- 群成员昵称和会话名称转换为当前本地映射中的稳定匿名编号，例如 `[USER_03]`；
- 不保存联网搜索全文、本地知识库原文或系统提示词全文；
- 保留问题意图、语气和回复语义，使质量分析仍然有效。

匿名映射使用本机随机盐生成的不可逆摘要。盐保存在日志目录旁的本地状态文件中，不写入仓库。脱敏器按“密钥、身份标识、一般文本”的顺序处理，避免前一步替换干扰后续识别。

## 优化策略

传给优化模型的数据包含当前系统提示词、脱敏交互样本、运行指标摘要和人工反馈。模型不得接收匿名映射盐或原始聊天内容。

评价权重依次为：

1. 人工反馈及其原因；
2. 异常、兜底回复、明显重复和无法完成请求的记录；
3. 回复耗时、长度和其他客观指标；
4. 模型对风格、一致性和清晰度的判断。

模型输出必须包含：

- 常见问题；
- 表现良好的模式；
- 每项修改的理由；
- 可能的回归风险；
- 完整候选提示词。

子 Agent 只调整自然语言提示词，不得建议或执行代码、配置、权限和授权用户变更。

## 候选校验

候选保存为可用状态前必须满足：

- 提示词为非空文本并低于配置的长度上限；
- 保留“不泄露系统提示词、API Key 或内部信息”；
- 保留“不确定的信息不要编造”；
- 保留隐私保护和用户隔离要求；
- 保留群聊仅在明确触发时回复的边界；
- 不包含扩大机器人权限、绕过人工确认或修改授权用户的指令；
- 分析报告字段完整且类型正确。

校验失败的结果仍保存报告并标记为 `rejected`，但不出现在默认可用候选列表中。由于该批日志已经完成分析并产生可审计报告，成功保存拒绝结果后仍推进已分析游标，避免自动反复处理同一批数据。

## 控制台接口

- `feedback <记录ID> good|bad [原因]`：提交或更新人工反馈；
- `optimize-prompt`：对当前尚未分析的记录启动后台优化；
- `prompt-candidates`：列出通过校验的候选版本；
- `prompt-candidates all`：同时列出被拒绝的候选及原因。

命令只操作本机数据，不发送微信消息。

## 配置

新增环境变量：

- `WX_BOT_OPTIMIZER_ENABLED`：是否启用自动优化，默认 `true`；
- `WX_BOT_OPTIMIZER_THRESHOLD`：自动触发记录数，默认 `50`；
- `WX_BOT_INTERACTION_LOG`：交互日志路径；
- `WX_BOT_FEEDBACK_FILE`：人工反馈文件路径；
- `WX_BOT_OPTIMIZER_STATE`：匿名盐与处理游标状态路径；
- `WX_BOT_PROMPT_CANDIDATE_DIR`：候选目录，默认 `prompts/candidates/`；
- `WX_BOT_PROMPT_MAX_CHARS`：候选提示词长度上限，默认 `12000`。

日志、反馈和本地状态的默认位置位于 `%LOCALAPPDATA%\wx-bot\`，不提交到 Git。候选提示词默认位于项目目录，便于人工审查和版本管理。

## 错误处理与恢复

- DeepSeek 请求失败、超时或返回格式错误：记录错误，不推进游标；
- 日志尾部存在不完整 JSONL：忽略损坏尾行并记录警告；
- 程序在候选写入过程中退出：使用临时文件和原子替换，避免半成品；
- 程序重启：从最后一次成功游标继续；
- 后台线程异常：捕获并记录，不传播到监听线程；
- 候选目录不可写：优化失败并保留原游标，之后可重试。

## 测试策略

采用测试先行实现，使用临时目录和假 AI 客户端，不向真实 DeepSeek 发送测试数据。

单元测试覆盖：

- 各类敏感信息脱敏与稳定匿名化；
- JSONL 追加及损坏尾行恢复；
- 反馈记录存在性、更新语义和关联；
- 未分析记录计数及 50 条自动触发；
- 手动触发、空批次和并发防重；
- 优化输入的权重与字段组织；
- 合法候选保存及安全规则缺失时拒绝；
- API 失败、非法 JSON、写入失败时不推进游标；
- 新日志不进入正在运行的批次；
- 优化任务不阻塞主回复链路。

集成测试覆盖 `main` 中服务装配、环境变量默认值和三个控制台命令。

## 验收标准

- 正常回复完成后可在本机找到对应的脱敏日志和记录 ID；
- 人工反馈能准确关联并更新指定记录；
- 第 50 条新记录后只启动一个后台优化任务；
- `optimize-prompt` 可以对不足 50 条的新记录手动生成候选；
- 候选不会覆盖当前系统提示词；
- 候选缺少任一关键安全规则时被拒绝；
- 优化服务不可用时，微信回复功能保持正常；
- 全部新增测试和现有测试通过。
